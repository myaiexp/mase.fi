# Base Components

Shared web components library built from `src/components/` via Vite library mode.

- **Build:** `pnpm build:components` → `dist/base-components.js` (IIFE)
- **URL:** `https://mase.fi/base-components.js`
- **Components:** `<base-badge>`, `<base-modal>`, `<base-tabs>`/`<base-tab>`, `<base-dropdown>`/`<base-dropdown-item>`/`<base-dropdown-divider>`, `<base-select>`/`<base-option>`/`<base-option-group>`, `<base-text-fit>`, `<base-context-menu>`
- **Toast:** `window.BaseToast.show(message, type, duration)` — no HTML tag, static API. Types are `success`, `error`, `warning`, and `info` (the default; any other type is `info`). Light DOM: it stamps base.css's `.toast-container` / `.toast` / `.toast-<type>`, and position (bottom-right), z-index (200 — above `.modal-backdrop`, below `<base-modal>` and `<base-context-menu>` at 1000), padding, border and type color live only in that recipe. Entrance is `.toast`'s `toast-in`; the timed dismiss is a CSSOM opacity fade.
- **Badge:** `<base-badge type="tag|status" variant="…" size="sm" color="…">label</base-badge>`. `type` defaults to `tag`. Tag variants: `feature`, `security`, `chore`. Status variants: `running`, `idle`, `queued`, `error` — `type="status"` also draws the dot. `color` overrides the variant colour. `size="sm"` is the shorter chip. An unknown variant with no `color` leaves the chip uncoloured. No properties, no events.
- **Modal:** `<base-modal>` slots are `header`, the default body, and `footer`. Call `open()` / `close()` — do not set the `open` attribute by hand. `open()` sets `open` (that attribute is what displays the dialog), traps Tab, and focuses the first slotted control, else the shadow `[x]` button. A second `open()` while open does nothing. `close()` removes `open` and dispatches a bubbling `close` event; Escape, the `[x]` button, and a backdrop click call it, a click inside the dialog does not. `isOpen` follows the methods.
- **Tabs:** `<base-tabs>` contains `<base-tab label="…" active disabled>panel</base-tab>`. The `active` attribute picks the initial panel, else the first. `activeIndex` reads and sets the selection; an out-of-range or disabled index does nothing. Selecting (click, arrow keys, or `activeIndex`) moves `active` and dispatches a bubbling `tab-change` with `detail: { index, label }`. The initial build does not dispatch. Arrow keys skip disabled tabs; Enter or Space re-selects the current tab.
- **Dropdown:** `<base-dropdown>` with a `slot="trigger"` element and `slot="items"` children: `<base-dropdown-item value="…" disabled variant="danger">` and `<base-dropdown-divider>`. The trigger click toggles. `open()` / `close()` / `isOpen`. Choosing an enabled item dispatches a bubbling `select` with `detail: { value }` and closes; a disabled item does not. Arrow keys move among enabled items, Enter chooses, Escape and an outside click close.
- **Select sizing:** `<base-select>` is **intrinsically sized** — it takes the width of its widest option (a hidden sizer mirrors every label plus the placeholder, so the control doesn't twitch when the value changes), like a native `<select>`. Add the **`stretch`** attribute to fill the container instead, matching base.css's `.btn-stretch` idiom. It shrinks below its intrinsic width when the container is narrower (`min-width: 0` + `max-width: 100%`), and the trigger ellipsizes rather than overflowing. Consumers should not need to pin a width; do so only for a deliberately fixed control. (Before 2026-07-20 the host defaulted to `width: 100%`, which was invisible in a nowrap flex row but claimed a whole line once that row wrapped — every consumer patched around it.)
- **Select:** `<base-select value placeholder searchable disabled size="sm">` with `<base-option value disabled action>` and `<base-option-group label>`. `value` is the attribute and the property; setting the property does not fire `change`. `placeholder` shows when nothing is selected. `searchable` makes the trigger a filter input (case-insensitive substring on the option label). On a searchable control, the first `open()` clears the trigger so the selected label is not the query, and `close()` writes the label back and resets the filter; a second `open()` leaves an in-progress query alone. `disabled` refuses to open. `size="sm"` shrinks the trigger. Choosing an option sets `value` and dispatches a bubbling `change` with `detail: { value, label }`. An `<base-option action>` adds a `...` button that does not select: it dispatches a bubbling `option-action` with `detail: { value, label, anchor }` and leaves the menu open. Without `searchable`, a letter moves the highlight and does not select.
- **Text-fit:** `<base-text-fit lines="2" mode="wrap">…</base-text-fit>` — pretext-measured truncation/wrapping of its text content. Attrs: `lines` (max, default `1`; `0` = unlimited), `mode` (`fit` default = ellipsis truncate, `wrap` = balanced binary-search wrap, `justify` = word-spacing justify), `hyphenate` (no-op stub, warns once). Auto-sets `title` to full text and keeps it in step with content changes (an author-set `title` is left alone); reflows on resize/content-change/font-load. No custom events.
- **Context-menu:** singleton — place one `<base-context-menu>` in the DOM (it listens for `contextmenu` on `document`). Imperative API: `register(id, {selector, items, touch})` (zone matched via `target.closest(selector)`; `items(target, selection, ctx)` callback returns an item array, or `[]`/falsy to fall through to the native menu; `ctx` is `{x, y, pointerType}` — the press coordinates and the resolved gesture, `'touch'` or `'mouse'`), `unregister(id)`, `show(x, y, items)`, `close()`, `isOpen` getter. Item shape: `{label, action}`, `{separator: true}`, optional `disabled: true`. Keyboard nav (↑/↓/Enter/Esc), viewport-edge flip clamped inside the viewport; closes on outside-click/scroll/blur. No custom events — selection runs the item's `action()`. **Touch long-press is opt-in per zone (`touch: true`), and off by default** — a long-press fires `contextmenu` too, but on a touchscreen it is also the gesture that starts a text selection, so `preventDefault()`ing it leaves the page unselectable with no way to copy anything (helm's detail view, 2026-07-28). A zone takes the gesture only when it offers something better than the browser's selection handles — helm's event stream does, with a copy ladder built from `ctx.x`/`ctx.y`; its editable-field and body-wide selection zones don't and stay native. Detection prefers the event's own `pointerType`/`mozInputSource` and falls back to the preceding `pointerdown` (engines disagree on which the `contextmenu` event carries), with `keydown` clearing it so a Menu-key press isn't read as a finger.
- **Theming:** Shadow DOM with `base.css` custom properties (`--bg-raised`, `--accent`, `--green`, etc.)
- **CSP contract:** components work under a strict `style-src 'self'` — no `'unsafe-inline'` needed. Each component's CSS is a constructable `CSSStyleSheet` adopted on its shadow root (`shared/shadow-styles.js`: one sheet per component per document, shared by every instance), which CSP style-src does not govern; an inline `<style>` in a shadow root *is* governed, and blocked it leaves the host `display: inline` with the select's width-sizer labels showing as text (news, 2026-09-22). Engines without `adoptedStyleSheets` (jsdom) fall back to a `<style>`. Never add a `<style>` to a template or a `style="…"` attribute to shadow markup; CSSOM writes (`el.style.x = …`, `style.setProperty`) are fine — CSP does not govern them. Toast stays light DOM for that reason: its look is the classes above, and the dismiss fade is a CSSOM opacity write rather than a shadow stylesheet.
- **Upgrade order:** a consumer may create the elements and set properties before `base-components.js` has defined them (Vite hoists the app bundle into `<head>`, ahead of the library `<script>`). `shared/upgrade-properties.js` replays any own property that shadows a class setter (`select.value`, `tabs.activeIndex`, and any setter added later — the list is read from the prototype) through the setter on connect.
- **Member convention:** Inside a component class, `#member` is hard-private internal state; `_member` marks a member deliberately reachable by a **friend module or test**. Default to `#`; use `_` only when something outside the class must read it. Current `_` members: `select._menu` / `select._selectOption` (read by the friend module `select-menu.js`), `modal._handleKeyDown` / `modal._getFocusableElements` / `modal._getLightFocusables` (exercised by `modal.test.js` and `modal-focus.test.js`), `tabs._updateTabs` (called by the sibling `BaseTab` class on attribute changes and by `tabs.test.js`), and `component._overlayListeners` (stamped on by `shared/overlay-utils.js`). `select`, `modal`, and `tabs` keep `_` members and state the convention at the top of the class; `context-menu`, `dropdown`, and `badge` state it and are fully `#`; `text-fit` and `toast` do not restate it.
