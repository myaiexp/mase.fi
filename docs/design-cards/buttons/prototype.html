.btn

One size, three variants — all rendered from base.css. Default is the baseline; primary earns its amber; danger is red. Hover any button — they're live.

Variants

Default · Primary · Danger

22px tall, --text-sm / 500, square. Most buttons are default. Primary marks the one most-forward action in a pane; danger is destructive — same shape, red instead of amber (both tint via color-mix, so a re-themed --accent / --red re-tints them).

Modifier

.btn-stretch — flanking a growing control

The one sanctioned escape from the fixed height. A composer's send/attach buttons sit in a flex row with an auto-growing textarea; without this they pin to 22px and float at the top of a tall row. --btn-h stays the floor, so a stretch button in a one-line row is indistinguishable from a normal one.

Opt-in per call site. Don't reach for it to make a button "bigger" — one size still governs every ordinary button; this exists only for the flanking case.

Legacy

Deprecated — .btn-sm · .btn-ghost

Not part of the one-size/three-variant vocabulary. Retained in base.css only so existing consumers don't break (~250 .btn-sm, ~24 .btn-ghost across the fleet). Don't reach for them in new work — removing them is a separate migration.

.btn-sm — 18px. For a genuinely tighter control, use a 16px icon-only affordance instead.
.btn-ghost — borderless reads as a link. Prefer a real .btn or an actual <a>.
Rules

What not to do

Real .btns with one property forced wrong, so the contrast reads.

❌ two amber — the eye can't pick the action. One primary per pane.
❌ wrapping → shorten to . Buttons never wrap.
❌ radius — the system is square (--radius: 0).
