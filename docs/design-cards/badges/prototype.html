base-badge

Three recipes. Status (dot + tint), tag (tint), inline (dot on a row). Pick by role — don't mix.

Recipe A

Status — live state

Dot carries the "changing" semantic. 8% tint on color (4% on neutral idle).

default running idle queued failed
size=sm running idle queued failed
in copy deploy finished — running on helm
Recipe B

Tag — classification

No dot. Dots on static labels read as "something is happening" and mislead.

default feature security chore
size=sm feature security chore
color= accent cyan purple custom hex
Recipe C

Inline — metadata strip

No chip. A 6×6 dot stuck into a row of dense metadata. Lives on arbitrary parents (.card-meta, etc.) — that's why it's not the <base-badge> element.

What not to do

These render so the contrast reads — each is wrong for a specific reason.

❌ dot on tag feature — reads as live state
❌ weight 600 feature — too heavy on a 16px chip
